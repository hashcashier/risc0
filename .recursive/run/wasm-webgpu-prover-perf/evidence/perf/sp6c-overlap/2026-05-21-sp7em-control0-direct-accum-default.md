# SP7em - CONTROL0 Direct Accumulator Default

Date: 2026-05-21

## Objective

Replace the CPU RV32IM TopAccum work for `major7=CONTROL0` with a narrow
direct WebGPU accumulator kernel, without using the rejected generated
CONTROL0 TopAccum arm shape from SP7el.

The generated arm remains rejected: SP7el showed CONTROL0 has `201625`
generated bytes, `58` inverse calls, and `22547036` xgboost inverse-items,
worse than previously rejected generated-arm candidates. SP7em instead
implements only the direct accumulation products for CONTROL0 rows and keeps
the existing witness path authoritative.

## Implementation

`webgpu.rs` now adds:

- `set_accum_gpu_control0_direct_enabled`
- `accum_gpu_control0_direct_rows`
- a thread-local `ACCUM_CONTROL0_DIRECT_KERNEL`
- `accum_control0_direct_wgsl()`
- `AccumMiscDirectKind::Control0`
- grouped dispatch support for CONTROL0 direct rows

The direct WGSL path uses `LAYOUT_TOP.inst_result.arm7` and emits the
CONTROL0 accumulator terms in this order:

- `arg1`
- `arg2`
- `memory_arg[0..16]`
- `cycle_arg[0..8]`
- `arg_u16[0..16]`
- `arg_u8[0..16]`

The generated term count is asserted at `58`. Prefix products are stored into
`ACC_COL0..18` every three terms and `ACC_COL19` for the final prefix.

`step_accum` now collects cycles whose `major == 7`, skips the CPU raw
TopAccum bit `1 << 7` only when the direct CONTROL0 row list is non-empty,
and dispatches the grouped direct accumulator kernel. With the existing direct
MISC/MEM paths active, the CPU TopAccum skip mask moves from `0x0046` to
`0x00c6`.

`enable_webgpu_witgen_accum_acceleration_for_hal` now enables CONTROL0 direct
accumulation by default.

## Performance Decision

Accept and enable by default.

Compared with same-tree pre-promotion defaults:

- BusyLoop + KeccakUnion: `98.70s -> 95.73s` (`-2.97s`)
- xgboost: `72.67s -> 68.02s` (`-4.65s`)

Compared with the accepted SP7ej baseline:

- BusyLoop + KeccakUnion: `96.96s -> 95.73s` (`-1.23s`, about `1.3%`)
- xgboost: `73.38s -> 68.02s` (`-5.36s`, about `7.3%`)

The xgboost movement is material for the current browser WebGPU state, and
the BusyLoop + KeccakUnion representative gate also moved in the right
direction while preserving receipt verification and zero-fallback assertions.

## Follow-Up

Do not retry generated CONTROL0 TopAccum. If continuing accumulator work, use
direct/narrow accumulator kernels only where focused term construction is
small enough to avoid the per-row split-inverse generated-arm failure pattern.

The next immediate work should stay on large measured buckets: chunk-complete
GPU witgen/accumulation or other paths that remove broad CPU-owned surfaces
without per-proof predispatch/prewarm regressions.
