# SP7gd Strided-Local NTT Simulation

Date: 2026-05-22

## Purpose

Sanity-check the SP7gc strided-local second-phase NTT mapping without changing runtime code while browser WebGPU validation remains blocked.

Current accepted working state remains SP7fr. Accepted wall-time gain: 0.

## Static Correctness Check

The WebGPU twiddle table is generated by appending powers of `BabyBearElem::ROU_FWD[s_bits]` for each stage. The current `NTT_STEP_WGSL` uses:

```text
stage_base = (1 << (s_bits - 1)) - 1
s = pair - g * s_size
twiddle = twiddles[stage_base + s]
```

For a second local phase after a fused block size `B = 2^f`, the equivalent fixed-intra-block-offset form is:

```text
s_bits = f + t
block_s_size = 1 << (t - 1)
s_original = block_s * B + intra_block_offset
twiddle = ROU_FWD[s_bits] ^ s_original
```

This matches the SP7gc formula:

```text
twiddle = twiddles[(1 << (stage - 1)) - 1 + s_original]
```

## Simulation

A local Python field simulation compared three paths over the BabyBear modulus and raw `ROU_FWD` values:

1. full CPU-style `expand` followed by all forward NTT stages;
2. current WebGPU shape: expand plus stages through `fused_bits` inside contiguous blocks, then global stages;
3. SP7gc candidate shape: same local prefix, then remaining stages over strided block-index vectors at each intra-block offset.

The sweep covered:

- `n_bits = 4..10`
- `fused_bits = 2..n_bits-1`
- `expand_bits = 0..min(3, fused_bits)`, including the proof-relevant `expand_bits=2` analogue

## Conclusion

The proposed second local phase is algebraically consistent with the current staged forward NTT for the tested small analogues. This removes the immediate twiddle-indexing concern from SP7gc.

This is not sufficient for acceptance. The remaining risks are browser-specific:

- strided global read/write coalescing may erase the theoretical memory-pass win;
- workgroup-local pressure and occupancy may differ at the real `fused_bits=10`, `n_bits=20` shape;
- only browser HAL parity plus BusyLoop, KeccakUnion, and xgboost proof gates can promote the candidate.

Next action when browser validation is available: implement the default-off SP7gc candidate with a focused HAL parity/perf marker, then run representative proof generation before retaining runtime code.
